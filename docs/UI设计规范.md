# CSUCampusCraft UI 设计规范

变体：standard（yellow / neutral / standard / contours / standard / full），默认浅色，可手动切换深色。
主视觉：校园文创品牌字标、真实商品封面与校园主题；控制台以数据库已有的五项计数组织版面，不创造统计数值。
页面类型：U01 展示页；用户端目录、详情与交易页面为阅读和操作页面；管理端采用统一命令栏，A02 为数据总览，其余为查询与维护页面。

## 范围与冻结边界

这是 STEP01–13 交付后的视觉增强，不改变业务验收范围。业务基线为 `e2bdeb9df9cc7888383ef7afa28d5fbe94f29696`。页面编号、标题含义、中文状态和业务说明、路由、HTTP 状态、303、参数、CSRF、会话隔离、七表结构及状态机继续沿用原实现。P1 确认收货仍未选做。

允许的修改为两端模板的包裹层、class、装饰性英文、可访问性属性，以及各端独立打包的 CSS、JavaScript、字体与纹理。原有 JavaScript 图片回退、表单提交提示和防重复提交逻辑完整保留；新脚本只补充主题与页面辅助反馈。禁用 JavaScript 时仍使用原生链接、表单和服务端跳转。

46 个模板的原始选择器清单与业务文本清单保存在本轮证据中。比较逐元素保留原 `data-*`、`id`、`name`、action、method 与 Thymeleaf 绑定。布局根节点新增的 `data-ef-variant`、`data-theme` 仅用于外观，不作为业务输入；新增控件不使用业务字段名。

## 变体选择

采用 standard，而非 site。黄块与墨色具有较高对比度，能清楚表达导航当前位置、主要操作及需要阅读的提示；中性纸面适合商品图片、收货信息和密集数据。site 的暖纸、大切角与更强斜线纹会增加商品图片和后台表格周围的视觉噪声，因此不采用。

设计依据为全局安装的 [endfield-ui skill](https://github.com/hhikr/endfield-ui-skill)，读取版本 `96702a36317b4c76538d1a20ed6beaae4e6067e2`。借用视觉规则、开放字体和通用纹理，不使用游戏字体、徽记、立绘、截图、角色或宣传文案，不在运行时读取技能目录。页面版面和中文内容由本项目自身数据与流程决定。

与技能示例的主要区别：校园主题和商品目录代替记录归档；毕业专区与真实购物车构成首页入口；控制台仅呈现五项现有计数及原筛选链接，不复制示例圆盘、六项看板、虚构读数或占位品牌。

## 视觉变量

### 色彩与线条

| 用途 | 浅色 | 深色 | 规则 |
| --- | --- | --- | --- |
| 页面纸色 | `#F4F4F2` | `#191919` | 主背景，避免纯白铺满 |
| 内容面板与输入框 | `#FFFFFF` | `#222222` | 直角、无柔和投影 |
| 正文与标题 | `#161616` | `#EDEDED` | 文字与有意义的边界 |
| 次要文字 | `#5C5C5C` | `#A3A3A3` | 不用低对比度灰字承载业务说明 |
| 装饰分隔线 | `#D9D9D6` | `#353535` | 1px；控件边界和焦点另用较深线 |
| 次级填充 | `#E4E4E0` | `#2E2E2E` | 次级按钮和轻量标签 |
| 唯一强调色 | `#FFFA00` | `#FFFA00` | 当前位置、可操作或注意事项；填充上用 `#161616` |
| 当前位置与焦点线 | `#161616` | `#FFFA00` | 浅色中禁止黄色文字或黄色细线 |
| 删除动作 | `#B3261E` | `#FF8A7A` | 仅真正删除；取消、禁用、下架和移除使用中性样式 |
| 管理端导航 | `#161616` / `#EDEDED` | 相同 | 两主题均使用深色导航 |

黄色面积保持克制，不做整页底色或大面积黄色横幅。提示与错误用墨字、可读边界和小黄旗，原错误码和文字完整显示。状态同时保留文字及边框、填充差异，不只依赖颜色。

页顶三色条为 3px 的品红、黄色、薄荷绿纯色小块，不用作表格分隔。纹理只使用本地 SVG 的细淡等高线或斜线；不使用装饰性渐变、发光、阴影、扫描线、假坐标、假条形码或伪造技术读数。

### 字体、间距和形状

| 项目 | 规范 |
| --- | --- |
| 拉丁字体 | 本地 Saira 可变字体；宽度轴 50–125，字重 100–900；保留 SIL OFL 1.1 许可 |
| 中文字体 | `Microsoft YaHei`、`PingFang SC`、`Noto Sans CJK SC` 等系统无衬线栈，不发起外部字体请求 |
| 英文眉题 | 11–13px、600、大写、约 0.14em 字距、125% 宽；仅为中文标题的直译或品牌补充 |
| 标题 | 桌面主标题约 40px，次标题 22–30px；移动端适当缩小；中文保持正常字距 |
| 正文与输入 | 正文 16–17px、舒适行高；输入字号至少 16px |
| 编号和金额 | 真实 SKU、订单号、分页、行序或数据库计数；数字使用 tabular-nums，不新增业务字段 |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px；手机页边距至少 16px |
| 边界与圆角 | 1px 分隔、2px 可见焦点；圆角 0、无柔和投影 |
| 切角 | 标签约 7px，按钮约 8px；只表示链接、按钮、可交互区域，文字与切角之间保留空白 |
| 点击区域 | 主要导航、按钮与控件至少 44px；紧凑的文本链接保留足够行高和间距 |

普通不可点击面板与商品图片容器保持直角。商品列表使用缩略图与信息排列成记录行；首页可用展示型商品组，原始商品数据与排序保持。表格行号来自当前可见行的自然序列，不伪装成主键或全局记录数。

字体位于两端各自 `static/css/fonts/` 下，纹理位于 `static/css/contours/` 下，遵循现有 `/css/**` 公开资源范围，登录前即可加载。两个 JAR 均包含完整资源，不跨端请求字体或 CSS。

## 组件与交互

| 组件 | 处理方式与保留项 |
| --- | --- |
| 导航与页脚 | 用户端商品与交易入口、真实购物车徽标；管理端分类、商品、订单、顾客与退出；原目标和表单保留 |
| 标题区 | 直译英文小标题在上，原中文标题与业务说明在下；展示页使用较大品牌字标 |
| 主题与筛选 | 强调当前项，查询仍由原 GET 表单提交；不新增自动筛选或改变分页参数 |
| 按钮 | 切角、单组主要操作突出；常规、hover、focus、disabled、提交中分别表达，不删除按钮 name/value |
| 表单 | 原 label/for/id、必填与错误绑定保留；说明和错误与字段相邻；摘要可聚焦并链接原字段 |
| 表格与分页 | caption、表头 scope、可聚焦滚动容器；行悬停、自然行序；原筛选、分页和跳转完整保留 |
| 状态 | “待支付”“已发货”“已取消”等原中文原样保留，结合边框和填充，不创造新状态 |
| 购物车与结算 | 明确条目、有效小计与金额；失效提示完整；金额、件数和徽标只读原服务端模型 |
| 订单与支付 | 成交快照、凭证、状态时间和教学模拟说明保持；原取消确认仍为原生 details/summary |
| 管理总览 | 五项真实计数采用主次布局；链接继续指向原有状态过滤列表，不做派生财务图表 |
| 商品相册 | 保留独立封面、相册排序和版本字段；相册维护仍使用原 POST/CSRF/版本契约 |
| 空态与错误 | 保留原原因、错误码、返回和重试链接；用轻纹理、黄旗、清晰标题表达，不隐藏冲突 |
| 主题切换 | 默认浅色，用户手动选择后保存在本端 localStorage；存储不可用时安全退回浅色；不写数据库 |

不新增自定义业务弹窗。原生取消确认、表单错误摘要、提示条与展开内容采用统一边界和间距；关闭 JavaScript 后仍可操作。

## 动效

| 场景 | 时长 | 缓动与限制 |
| --- | --- | --- |
| 按钮按下 | 100ms | 极小位移，无弹跳 |
| 行悬停、焦点反馈 | 200ms | `cubic-bezier(0.16,1,0.3,1)`，不移动表格整体布局 |
| 提示与原生确认内容出现 | 280ms | `cubic-bezier(0.7,0,0.2,1)` |
| 页头入场 | 320ms | 单次入场不超过 650ms，整体序列不超过 1 秒 |
| 商品图片 hover | 280ms | 小幅视觉回应，不改变图片与链接含义 |
| 按钮色彩过渡 | 160ms | `cubic-bezier(0.2,0.7,0.1,1)` |
| 原生确认收起 | 即时 | 不新增模态框或延迟关闭；不延迟实际请求、不拦截 303 |

动效只回应页面进入、hover、focus、展开与已有提交状态，不做循环装饰或滚动触发的逐段入场。`prefers-reduced-motion: reduce` 下关闭 animation、transition、平滑滚动，内容和操作完整可见。原表单提交状态保持，使用斜线表达处理中，不伪造百分比或成功结果。

## 响应式与可访问性

- 桌面验证 1366×768 与 1920×1080；移动验证 390 和 430 CSS px。容器、网格与 flex 子项允许收缩，长 SKU、订单号和错误文字可折行。
- 手机导航换行、筛选纵向排列、商品详情与支付结算分栏改为单栏。管理端宽表只能在自身可聚焦的容器内滚动，整个页面不能水平溢出。
- 保留 `lang="zh-CN"`、skip link、main、导航名称、原 label 和字段错误链接。键盘可到达全部操作，焦点在浅深两套主题均清楚可见。
- 表格具有 caption 和列标题；数字金额保持可读。错误保留 `role="alert"` 或原摘要，普通成功提示不伪装成业务错误。
- 非文本装饰 `aria-hidden="true"`。主题按钮具备名称与按压状态，脚本未运行时隐藏；不出现无效的操作入口。
- 浏览器实测包含：Tab 焦点、主题记忆、禁用 JS、reduced-motion、外部请求检查、label 关联和不同宽度的 document overflow。检查结果和任何未覆盖项单列在新证据中，不把自动检查等同于完整辅助技术认证。

## 实现与维护

两端共享 CSS/JS 的源内容保持字节一致，通过 `.ef-app-user` 与 `.ef-app-admin` 区分布局。原组件 class 保留，新设计类统一使用 `ef-` 前缀。静态资源在各工程下各有一份，发布包不依赖技能目录、CDN、前端框架、字体服务或新的构建工具。

改造前后截图、选择器清单、双端构建日志、85 元链路及权限/CSRF/版本冲突回归、七表观察、可访问性检查、敏感扫描与清理结果见 [UI 重设计证据](evidence/2026-11-15-ui-redesign/README.md)。本次证据与 STEP01–13 的历史实测分开归档，旧截图、旧失败及受测 SHA 保持原样。
