# CSUCampusCraft 需求与业务规则

本规范描述以中南大学校园文创为主题的教学模拟商城。游客可以浏览，普通用户购买并管理本人订单，管理员维护分类、商品、相册和库存，管理普通顾客启用状态，查询订单并模拟发货，控制台呈现真实状态数量。MySQL 8.4 与 InnoDB 是项目的数据基线。当前已交付范围与实测状态见 [README 的「当前阶段」](../README.md#当前阶段)和[《测试与验收用例》的实测记录](测试与验收用例.md)。

范围及阶段门槛见[项目立项与范围](项目立项与范围.md)。编号在修改时保持稳定，页面、路由和测试分别引用对应的 REQ 与 BR。P0 是首版必交，P1 是通过 P0 后可选的范围。

## 身份和目录规则

### BR-01 身份与归属

游客可读已上架商品。用户端认证要求启用的 `CUSTOMER`，管理端认证要求启用的 `ADMIN`。两端分别用独立会话 Cookie，使用 BCrypt 校验密码散列，强度参数固定为 cost 10，登录后更新会话标识。两个工程均直接依赖 `spring-security-crypto`，使用 `BCryptPasswordEncoder(10)`，种子教学口令仍为 `CSUCampusCraft123!`，不把明文口令写回账号表。退出只结束本端会话。教学账号由种子提供，测试输入不得带真实地址或其他个人信息。

登录成功时将数据库 `store_user.updated_at` 的 UTC 微秒原值存为服务端会话 `authStamp`。保护页面和写操作每次从会话获取用户 ID，再从数据库检查账号状态、角色、数据归属及 `updated_at` 是否与 `authStamp` 一致，不接受客户端提供的标记，不按页面格式化时间比较。账号不存在、被禁用或时间标记不一致时清除本端身份和结算确认，并进入本端登录。重新启用后必须重新认证，禁用期间没有访问过的旧会话也不恢复。购物车、结算确认及本人订单只按该用户范围读写。客户端的用户 ID、角色、价格或权限标记均不作为授权依据。全部受保护数据库业务写在 Service 事务内先锁当前操作者的 `store_user` 行，复核启用状态、角色与会话 `authStamp`，通过后再锁业务目标。统一锁序为操作者用户行 → 订单或目标 CUSTOMER 等业务目标行 → 涉及商品按 ID 升序。只有纯会话登录、退出不属于此类数据库业务写。后台启停先锁 ADMIN 操作者、再锁目标 CUSTOMER，禁止反向取得这两类用户锁。未登录时进入本端登录，登录后回到允许的本端 GET 页面，原写请求由用户重新确认。

### BR-02 分类层级与类型

一级表示校园主题，二级表示文具或纪念周边。同一主题下每种二级类型最多一个。二级编码由一级编码和 `_STATIONERY` 或 `_SOUVENIR` 组成，例如 `LANDMARK_STATIONERY`。一级编码去首尾空白后须为 1–21 字符。最长后缀 `_STATIONERY` 为 11 字符，21 + 11 正好满足二级 `code` 的 32 字符上限。完整二级编码由服务端生成，最长 32 字符，一级 22 字符即返回 400，禁止截断后保存。分类创建后编码和父类固定，可修改名称和排序。同父名称与全站分类编码按不区分大小写校验唯一。禁止三级、自引用和循环分类。分类删除要求既无子类也无任何商品引用，包含下架商品。

商品仅可归入二级类目。列表以一级 `categoryId` 和 `type` 表达主题及类型。未选主题时，类型跨主题过滤。二级导航进入列表时，将条件规范化为父主题 ID 与对应类型，切换类型时以新条件替换旧二级筛选。首批五个主题由数据库提供，后台新增符合规则的主题后前台可查询。

### BR-03 商品展示与维护

一个商品一个 SKU，SKU 创建后固定且全局不区分大小写唯一。新商品为 `DRAFT`，录入合法二级类目、名称、介绍、封面、售价和初始库存后可上架为 `ON_SALE`。管理端通过下架使商品退出公开购买。公开目录和商品详情只展示上架商品。库存为 0 时可展示「售罄」，商品下架后直接访问详情返回不可用。

首页「新品上架」按创建时间和 ID 倒序最多 3 件，「精选推荐」按排序值和 ID 升序最多 4 件，同一商品可以出现在两栏。详情展示面包屑、名称、SKU、价格、可售库存、纯文本设计说明、封面及按排序值和 ID 升序排列的相册。相册为空回退封面，资源缺失回退站内占位图。仓库保留历史订单所引用的资源。

### BR-13 查询、排序与分页

用户商品列表参数为 `categoryId`、`type`、`q`、`sort`、`page`、`size`。类型取 `ALL`、`STATIONERY`、`SOUVENIR`，缺省 `ALL`。查询词去首尾空白、最长 120 字符，以商品名包含匹配，通配符按字面处理。空串表示不限名称。后台商品列表可叠加草稿或上架状态。

| 排序值 | 稳定顺序 |
| --- | --- |
| `DEFAULT` | `sort_order ASC, id ASC` |
| `PRICE_ASC` | `price ASC, id ASC` |
| `PRICE_DESC` | `price DESC, id ASC` |
| `NEWEST` | `created_at DESC, id DESC` |

商品浏览缺省每页 6 条，其他列表缺省 10 条，每页 1–50 条。页码缺省 1，小于 1 的整数按 1 处理，错误类型或越界条数返回参数错误。改变条件回第 1 页，翻页保留条件。超过末页展示空状态并提供返回有效页的入口，数据和计数使用相同过滤条件。两端订单查询按完整单号精确匹配且不区分大小写，去首尾空白后最多 40 字符，空值表示不限单号，可叠加状态，按 `created_at DESC, id DESC` 展示。用户端始终限本人，管理端可查全站，并可用可选的正整数 `userId` 限定某个既存 CUSTOMER，格式错误为 400，不存在或非 CUSTOMER 为 404。普通顾客列表只取 `role=CUSTOMER`，用户名查询 `q` 去首尾空白后最多 50 字符，按字面包含匹配，状态为 `ALL`、`ENABLED` 或 `DISABLED` 且缺省 `ALL`，按 `id ASC` 展示，默认每页 10 条，分页使用本规则。

### BR-14 毕业专区与独立礼盒

首页毕业横幅按 `GRADUATION` 定位一级主题，进入复用的商品列表，仍可搜索、切换类型、排序与翻页。中南毕业纪念礼盒 `CSU-GRAD-BOX-01` 属于 `GRADUATION_SOUVENIR`，由地标明信片、毕业徽章、毕业帽钥匙扣组成，种子售价 49.00 元每盒。礼盒是独立 SKU，按盒销售、补货和返还，组成单品各自计库存。演示对已导入礼盒做上下架，新增商品另用未占用的测试 SKU。

## 交易规则

### BR-04 购物车数量与版本

一账号与一商品组合唯一，重复加购累加。每个 SKU 合计数量为 1–99 的整数，整车至多 20 种 SKU。添加和修改时校验上架状态及当前库存，修改或移除校验条目版本。已失效的条目可以移除。写车时锁住当前用户行，并在锁后复核启用状态与会话 `authStamp`，同账号并发加购不会生成重复记录，旧版本拒绝覆盖。

购物车由数据库持久化，退出登录和重启后保留。导航徽标使用 `SUM(cart_item.quantity)`，只按当前普通顾客 ID 过滤，包含下架、售罄、超库存等失效条目，不按行数、有效行数或有效小计计算。游客显示 0。用户端各业务页使用同一服务端读口径，成功加购、改量、移除及下单清车后的 303 目标页重新查询徽标，重新加载其他页面也须显示当前值。下架、售罄或所需数量超过库存时指出原因，保留条目以便用户调整。打开购物车和加购只检查库存。订单提交时扣减库存，待支付订单取消时返还。

### BR-05 整车结算与确认快照

结算以本人当前完整购物车为单位。空车、任一失效条目或库存不足均阻止结算。确认信息存于服务端会话，绑定本人，记录全车条目 ID、商品 ID、数量、条目版本和确认时单价。表单携带本端确认令牌。每个用户端会话保留最新一份，默认有效期为 10 分钟并可由服务端配置，从生成时间起算。重开确认、超时、提交成功或会话结束后，旧确认失效。确认期间不持有数据库锁，也不预留库存。提交重新比对整车，新增、移除、改数量、版本或单价变化均要求重新确认。字段校验失败时保留仍有效的确认及可回显信息。业务冲突保留购物车，令该确认失效并提供重新确认入口。

收货人、联系电话和完整地址必填，去首尾空白后分别为 1–50、1–30 和 1–255 个字符。收货地址用于模拟配送。打开结算页只生成确认，无库存或订单写入。

### BR-06 金额与成交快照

前端展示服务端计算的单价与小计，客户端金额字段不参与成交计算。金额用 `BigDecimal` 和 MySQL `DECIMAL(12,2)`，币种人民币，价格须为可表示的正数且最多两位小数。服务端先校验每条小计和总额均在精度范围内，再写库。行小计等于成交单价乘数量，订单总额等于明细小计之和。

创建订单时保留收货人、电话、地址及 SKU、商品名称、封面路径、单价、数量、小计快照。订单和支付使用已保存的总额，历史详情读取快照。后续编辑商品或账号信息不会改写成交记录。

### BR-07 锁顺序与原子下单

在 Spring 管理的 Service 事务内使用 MySQL `READ COMMITTED`。先锁当前用户，复核其启用状态与会话 `authStamp`，再核对当前整车与确认快照。按商品 ID 升序用 `SELECT … FOR UPDATE` 锁定所有涉及商品，从锁返回的行重验价格、状态和库存。库存扣减附库存下限条件，并核对更新行数。

一次事务写入一张 `PENDING_PAYMENT` 主单与全部明细、扣减各商品库存并递增版本、只清理本次确认且核对过的车条目。任一环节失败整体回滚。同账号并行提交同一确认最多成交一次，旧确认也不可清理后续新加购条目。其他用户争抢同一 SKU 的结果由 BR-11 判定。

### BR-08 订单状态机

| 当前状态 | 可用操作 | 成功后的状态 |
| --- | --- | --- |
| 待支付 `PENDING_PAYMENT` | 本人模拟支付成功 | 待发货 `PAID` |
| 待支付 `PENDING_PAYMENT` | 本人模拟支付失败 | 待支付 `PENDING_PAYMENT` |
| 待支付 `PENDING_PAYMENT` | 本人取消 | 已取消 `CANCELLED` |
| 待发货 `PAID` | 管理员发货 | 已发货 `SHIPPED` |
| 已发货 `SHIPPED` | 本人确认收货，仅 P1 启用时 | 已完成 `COMPLETED` |
| 已完成 `COMPLETED` 或已取消 `CANCELLED` | 查询 | 保持原状态 |

状态动作校验身份和旧状态。发货与确认收货保留首次时间，重复请求返回已处理结果。支付后至发货、确认收货期间均只改变订单状态与相应时间。两端查询使用同一状态词，数据库业务时间为 `TIMESTAMP(6)`，初始化和应用连接均使用 UTC，页面转换为 `Asia/Shanghai` 展示。待支付库存通过本人取消释放。

### BR-09 模拟支付

本人从待支付详情进入支付页面，按订单原金额执行「模拟成功」或「模拟失败」。写事务先锁当前操作者并复核身份，再锁本人订单并校验状态。成功写 `MOCK`、唯一支付凭证和首次时间，订单转待发货。失败保留待支付状态及空支付字段。重复成功返回首次支付信息。已取消订单拒绝支付，支付过程库存不发生变化。

### BR-10 取消与返库

待支付单由本人取消。取消先锁当前操作者并复核身份，再锁本人订单并核对状态，再按商品 ID 升序锁定并恢复各明细购买数量，递增库存版本，与取消时间及状态同事务提交。下架商品仍返库且保留下架状态。重复取消反馈原结果，不再返还。购买者若再次购买，重新加入购物车。支付与取消竞争同一订单锁，只允许一个迁移成功。

### BR-11 库存并发与商品版本

商品资料、价格、状态和库存发生实际变动，以及相册行实际新增、修改、删除时，均递增 `product.version`。商品编辑页显示只读库存，写资料时检查原版本。补货按正整数增量更新数据库的当前库存并递增版本。库存与金额采用有界类型，溢出时返回失败且不提交部分结果。

两个账号均确认同一 SKU 最后一件时，首先取得商品行锁并提交的一方产生订单，后一个事务锁内读到库存为 0。预期仅一张主单和一条明细，库存为 0 且版本只增一次。失败方收到库存不足提示，保留购物车，订单和明细无残留。购买与补货并发按数据库当前库存增减，两项均成功时，库存 10 减 2 加 3 得 11。

## 通用实现规则

### BR-12 HTTP、校验与页面安全

读页面使用 GET，HTML 表单业务写使用 POST。写操作由服务端校验输入、角色、归属、状态及 CSRF。成功后返回 303 并重定向到可读页面，刷新结果页不会重放写请求。权限错误及 CSRF 失败返回 403，非法参数返回 400，不可用商品或分类返回 404。旧确认、版本、库存和状态冲突返回 409 并指明可恢复动作。加购的具体边界见下表，售罄是上架商品的库存冲突，使用 409。身份缺失、会话过期、账号不存在或禁用时进入本端登录，不按库存或参数冲突处理。已认证但角色错误和 CSRF 错误使用 403。技术异常返回通用错误页，避免泄露内部异常信息。商品描述、收货信息和校验回显以转义的普通文本渲染。

### BR-15 初始化与静态资源

两端使用各自的端口和会话标识，连接同一个 MySQL 数据库。正常启动读取已有数据，结构版或完整种子版由操作者在预建空库择一导入。MySQL 建表语句隐式提交，种子数据的业务表写入在单个 DML 事务中执行。两端首个 GET 首页都通过数据库查询读取一级主题，库中无主题则展示空状态。应用重启保留购物车、订单与库存。共享图片在 `assets/images/` 维护一次，构建时进入两端静态资源，同一路径可从两端独立读取。


### BR-16 普通顾客管理边界

管理员只查询和启停 `CUSTOMER`。顾客详情可展示 ID、用户名、显示名、启用状态、教学邮箱、教学电话和创建时间，不向页面或日志输出密码散列。首版无账号创建、删除、资料修改、改密、密码重置及角色调整。详情中的订单入口带 `userId` 进入 A06，查询仍使用管理端鉴权与订单过滤。

状态写入使用路径 `userId` 和 `targetStatus=ENABLED` 或 `DISABLED`，在事务内先锁当前 ADMIN 操作者并复核身份，再锁目标用户行后重新核对目标角色。目标不存在或不是 CUSTOMER 返回 404，非法 ID 或目标状态返回 400。只有状态实际改变时更新该行，并将 `updated_at` 显式设置为 `GREATEST(CURRENT_TIMESTAMP(6), updated_at + INTERVAL 1 MICROSECOND)`，确保同微秒内的禁用、启用也有不同身份标记。重复目标状态按幂等成功处理，不写行并保留原更新时间。不同管理员并发启停按用户行锁串行生效，最终状态以最后提交的合法操作为准，不采用页面上的旧状态覆盖其他账号字段。

禁用事务提交后，该账号已有会话的后续保护请求重新读库，发现禁用或身份标记变化就清除本端身份及结算确认并要求重登。受保护业务写先锁操作者用户，锁后复核状态、角色及会话 `authStamp`，防止等待锁期间的启停变化被忽略。禁用不删除本人车、订单、成交快照，不自动取消待支付单或返库，管理员仍可查询订单及为既有 PAID 订单发货。启用只改变账号状态，顾客正常重新登录后继续访问已有数据。对禁用提交前已经进入业务事务的请求，仍由该事务的锁和提交结果判定，不宣称可撤销已经完成的交易。

### BR-17 相册资源、归属与版本

相册使用现有 `product_image`。每行绑定一个商品，`imagePath` 去首尾空白后为 1–255 字符的站内相对路径，以 `images/` 开头，不含外部协议、开头斜杠、反斜杠、查询串、片段或 `.`、`..` 路径段。`altText` 可空，去首尾空白后最多 120 字符，空值展示时回退商品名。`sortOrder` 是非负整数，空值为 0，展示按 `sort_order ASC, id ASC`，同排序值可并列。图片路径可复用，不新增唯一性约束。

每个写表单提交商品 `productVersion`。Service 先按 BR-01 锁当前操作者并复核身份，再锁路径商品、检查提交版本，随后查询属于该商品的图片。文中“先锁商品”均指完成操作者锁之后的业务资源锁步骤。新增、编辑、移除与商品实际增版在同一事务完成。商品不存在为 404，旧版本为 409，目标图片不存在或不属于路径商品为 404，失败时相册与商品版本均不变。编辑内容全部相同时视为无写入成功，不增版。真实变更令版本加 1，使旧商品或相册表单都要刷新，版本上溢则整笔回滚。

封面在商品资料表单单独维护，相册改动不改 `cover_image`。移除只删除相册行，首版不上传图片、不移动或删除仓库及运行包中的文件。移除末张相册后公开详情使用独立封面，封面资源缺失时使用站内占位图。历史订单仍读自己的封面快照，历史引用素材需保留。路径格式与图片能否加载分别检查，合法路径的缺图使用占位图，交付前补齐两端素材可访问证据。

### BR-18 控制台统计口径

A02 仅启用 ADMIN 可读。卡片全部从数据库当前已提交数据读取，统计每个真实表行，不使用演示常量或按商品库存求和。商品卡分别统计 `product.status=ON_SALE` 和 `DRAFT` 的商品数，售罄但上架的商品仍计入 ON_SALE。待发货卡统计 `sales_order.status=PAID` 的订单数，排除其他状态。顾客卡只统计 `store_user.role=CUSTOMER`，按 ENABLED 和 DISABLED 分组，排除管理员。

五项计数由同一条读语句取得，返回查询时点的一致快照，空表为 0。卡片分别链接 `/products?status=ON_SALE`、`/products?status=DRAFT`、`/orders?status=PAID`、`/customers?status=ENABLED`、`/customers?status=DISABLED`。列表或卡片刷新后读取最新已提交数据。查询失败显示可重试错误，不显示 0 或虚构数字。首版不统计销售额、利润、支付成功率或财务数据。


## 用户端功能流程

以下流程是首个业务版本的实现口径。端口、路径和表单参数见[系统设计与路由](系统设计与路由.md)。同一动作须同时满足页面入口、服务端权限和业务状态，直接提交请求时执行同样校验。

### 浏览、筛选与商品详情

适用 REQ-02、REQ-03 和 BR-02、BR-03、BR-13、BR-14、BR-15。

1. 游客进入首页时，读取一级主题和两栏上架商品。毕业专区用 `GRADUATION` 对应的一级 ID 打开商品列表，按 `type=ALL` 展示文具和纪念周边。若当前没有毕业主题，首页省略该专区入口，其他导航和搜索仍可使用。
2. 列表把主题、类型、关键词组成联合过滤条件，商品与总数使用同一套条件。以「毕业纪念 / 文具 / 书签」为例，结果必须同时满足三项。清除类型仍保留主题和关键词，切换主题或排序时重新从第 1 页取数。已有主题但没有匹配商品返回正常空页，未知主题返回 404，数字格式、枚举值或条数无效返回 400。
3. 关键词按字面包含匹配。使用 SQL `LIKE` 时，对输入中的 `%`、`_` 及转义符本身处理后再加包含匹配通配符。MySQL 标识采用 `utf8mb4_0900_as_ci`，按普通等值查询，区分重音且不区分大小写。完整订单号查询与 SKU、账号等标识遵循相同口径。
4. 商品详情按路径 ID 读取一件上架商品，并取其分类路径、封面和有序相册。无相册显示封面，图片缺失显示共享占位图。已下架与不存在的商品统一为 404。上架且库存为 0 的商品仍可浏览，显示「售罄」，直接提交加购也会被拦截。游客加购先登录，返回详情后由本人重新点击。

### 登录、退出与本人数据

适用 REQ-04 和 BR-01、BR-12。

1. 两端登录表单接收 `username` 和 `password`。用户名去首尾空白后须为 1–50 字符，密码须填写且按原样验证散列。缺少必要字段返回 400，格式合法但用户名、密码、角色或启用状态不符时使用统一失败提示，避免根据提示枚举账号。失败页可回显用户名，密码字段清空。
2. 登录成功更换本端会话标识。若需返回原页，目的地必须是本端允许的读路径。登录退出只影响本端，同一浏览器可同时持有顾客和管理员会话。退出后会话内结算确认作废，数据库中的本人购物车和订单保留。
3. 受保护页面和写入动作从会话取得当前账号，重新检查其角色、启用状态和资源归属。未登录跳到本端登录，角色、归属或 CSRF 不符返回 403。请求中的用户 ID 与角色字段不参与授权。顾客尝试读取或处理他人订单时，响应省略收货信息、金额和状态细节。

### 加购、改量与移除

适用 REQ-05 和 BR-01、BR-03、BR-04、BR-12。

| 动作 | 输入与前置 | 成功结果 | 失败与恢复 |
| --- | --- | --- | --- |
| 加购 | 已登录顾客提交正整数 `productId` 与 1–99 的整数 `quantity`。锁当前用户行后读取本人车和商品当前状态。 | 新商品增加一行，初始版本为 0。已有商品数量累加，同一 SKU 仍为一行，版本递增。303 跳转 U05，购物车和徽标读取提交后的数据。 | 字段格式或数量范围 400，未知或下架商品 404，售罄、超库存、合并超 99 或第 21 种 409。身份无效先本端重登，错角色或 CSRF 403。全部失败保留原数量、版本和条目。 |
| 改量 | 按本人 `itemId` 提交新的 `quantity` 和当前 `version`。 | 数量实际变化时递增条目版本。值相同且版本有效时保留原行与版本。 | 非整数和范围错误返回 400，旧版本或库存不足返回 409，提示刷新当前购物车。 |
| 移除 | 按本人 `itemId` 提交当前 `version`。失效条目也可移除。 | 删除该条目，其他条目和商品库存保持原值。最后一项移除后展示空车。 | 其他账号条目返回 403。条目已不存在返回 404，版本冲突返回 409，提示重新读取，避免误删后来更新的数据。 |

加购按下列顺序判定，避免相同请求出现多个随意状态码。先识别本端身份，再校验 CSRF、角色和参数，然后锁用户行并核对商品可用性，最后检查合并数量、种类及库存。已有 20 种时给其中一件增加数量仍可执行，不因车已满拒绝该动作。

| 加购情形 | HTTP 或导航结果 | 数据与恢复 |
| --- | --- | --- |
| 没有本端身份、会话过期，或账号不存在、已禁用 | 进入用户端 `/login`，清除失效身份及结算确认。 | 不执行加购，登录后回允许的商品读页，由本人重新点击。 |
| 已认证但角色错误，或 CSRF 缺失、错误 | 403。 | 原车保持，使用正确端登录或重新加载本端表单。 |
| `productId` 不是正整数、数量缺失或不是整数、数量不在 1–99 | 400。 | 定位字段，不修改购物车及库存。 |
| 商品不存在或状态为 DRAFT | 404。 | 提示商品不可用并可返回目录，原车保持。 |
| 商品 ON_SALE 且库存为 0、需求超过库存、累加后超过 99、新 SKU 使种类超过 20 | 409。 | 提示具体冲突与刷新、改量或移除入口，原条目、数量及版本全部保持。 |
| 以上全部通过 | 303 至 `/cart`。 | 数据库车更新，目标页按全车数量和重算徽标，商品库存不变。 |

购物车每次读取都重新计算现价和有效性，价格变化不需要改写购物车记录。下架、售罄或购买数量超出现有库存时保留该条目并显示原因。还有失效条目时，页面只能显示有效条目小计，并明确整车尚不可结算。加购、改量和移除均不改变可售库存，库存以提交订单时锁内读数为准。

### 整车确认与提交订单

适用 REQ-06、REQ-07 和 BR-04–BR-08、BR-11、BR-12。

1. U06 读取当前整车与现价。确认须有至少一条有效商品，且所有条目都可成交。空车或任一失效条目返回 409，清理旧确认并引导回 U05。有效确认在会话中保存令牌、生成时间、用户 ID 和条目 ID、商品 ID、数量、版本及单价。每次重新进入确认页会用新令牌替换旧令牌。
2. 提交表单发送 `confirmationToken`、`receiverName`、`receiverPhone`、`receiverAddress` 和 CSRF 令牌。收货字段不合规返回 400，保留可回显的地址信息和仍有效的确认令牌。订单金额、条目和用户均由服务端从确认和数据库中取得。
3. Service 在显式 `READ COMMITTED` 事务内先锁当前用户，再检查确认与当前整车完全一致。随后按商品 ID 升序锁商品行，重新判断是否上架、价格是否一致、库存是否足够，并在写库前核对每条小计和总额都可存入 `DECIMAL(12,2)`。任一项变化导致冲突时，整单返回 409，保留原车并要求重确认。
4. 全部校验通过后，生成不超过 40 字符的唯一订单号，写入待支付主单和全部明细快照。逐项扣减库存并递增商品版本，最后只清理已核对的购物车条目。任何写入行数与预期不符都回滚。提交成功后清理该确认，303 跳转本人订单详情。同一确认并发提交时，后到事务看到确认失效或购物车变化，不能重复成交。
5. 技术异常由事务回滚和通用错误页处理。若请求已发送但浏览器未取得结果，先回到本人订单与购物车核对，再决定是否重新确认。页面不得基于超时自行重发写请求。

### 查询订单与订单动作

适用 REQ-08–REQ-10、REQ-13 和 BR-01、BR-06、BR-08–BR-10、BR-12、BR-13。

- 列表显示本人订单号、创建时间、状态、总金额和详情入口，按时间、ID 倒序。详情在校验归属后显示主单与明细，使用创建时商品和收货快照。后来改名、改价、换图、下架都不会改写旧订单。种子中的已完成订单照常查询，P1 未选做时不出现确认收货动作。
- 待支付订单可进入模拟支付页。表单仅提交 `result=SUCCESS` 或 `result=FAILURE`，支付金额读取订单总额。模拟失败是一次合法尝试，303 返回本人详情并提示仍可支付或取消。首次成功写入 `MOCK`、唯一支付凭证和支付时间，转为待发货。待发货、已发货或已完成的订单重复模拟成功时返回原凭证，对这些订单模拟失败或对已取消单发起任意模拟支付时返回 409。所有支付尝试均不改库存。
- 取消事务先锁当前操作者并复核身份，再按订单号锁定本人订单。仅待支付状态能首次取消。恢复各条明细的库存并递增对应商品版本，写入取消状态与时间，全部在同一事务提交。商品已下架也按原数量返库，保持下架状态。已取消的重复请求返回原结果，已支付及后续状态拒绝取消。返库后订单留存，购物车不自动恢复。
- 启用 P1 后，已发货订单由本人确认收货，写事务先锁操作者并复核身份，再锁本人订单与状态，首次写入完成时间并转已完成，重复确认返回原结果。其他订单状态及未选做时直接请求该动作均不可执行。

## 管理端功能流程

### 分类创建、编辑与删除

适用 REQ-11 和 BR-01、BR-02、BR-12。仅启用管理员可执行。

| 动作 | 输入及校验 | 结果与副作用 |
| --- | --- | --- |
| 创建一级 | `name` 去空白后为 1–50 字符，`sortOrder` 为非负整数且空值默认 0。`code` 去首尾空白后为 1–21 字符的稳定编码，22 字符返回 400，保留 `_STATIONERY` 的 11 字符后缀空间。一级无 `parentId`。 | MySQL 通过 `AUTO_INCREMENT` 分配 ID，Mapper 回填。写入新的一级主题，用户端目录读取该主题。 |
| 创建二级 | 提交 `parentId` 与 `type`，类型只接受 `STATIONERY` 或 `SOUVENIR`。后端由父编码和类型生成完整编码，最长 32 字符。名称与排序按一级同样校验。 | 每个父主题下每种类型最多一条。不存在的父类按 404，父级不是一级、编码或同父名称已占用、类型冲突按 409。 |
| 编辑 | 路径分类 ID，表单仅允许编辑 `name` 与 `sortOrder`。名称仍需在同父级唯一。 | 编码、父类、已有商品引用保持原值。名称及排序变化可在用户端重新读取。 |
| 删除 | 先确认分类存在，再核对子类和任何商品引用，范围包括草稿和下架商品。 | 无引用时删除空分类。存在引用时返回 409，禁止级联删除。并发新增引用导致外键拒绝时，同样反馈引用冲突。 |

### 商品资料、上下架与增量补货

适用 REQ-11 和 BR-01–BR-03、BR-11–BR-14。后台商品表单按下表绑定，新增和编辑各自校验允许的字段。

| 字段 | 新建 | 编辑及校验 |
| --- | --- | --- |
| `sku` | 必填，去首尾空白后 1–40 字符，按数据库排序规则全局唯一。 | 只读，作为商品稳定标识。 |
| `categoryId`、`name` | 选择合法二级类目。名称去首尾空白后 1–120 字符。 | 可修改，仍限制为有效二级类目。 |
| `price` | 必填人民币正数，最多两位小数，范围 0.01–9,999,999,999.99。 | 服务端先检查精度与范围，再写入。 |
| `summary`、`description` | 摘要可空、最多 500 字符。详情可空，按纯文本存储并校验 UTF-8 编码后不超过 `TEXT` 的 65,535 字节。 | 可修改，展示时按文本转义。 |
| `coverImage` | 可空，空值使用站内占位图。提供时使用 `images/` 开头的站内相对路径，最多 255 字符。 | 可修改，拒绝绝对 URL 和路径穿越。缺图按共享占位图处理。 |
| `stock`、`sortOrder` | 初始库存和排序为非负整数，空值默认 0。 | 库存只读，通过独立补货动作更改。排序可编辑。 |
| `version` | 初始版本为 0，服务端生成。 | 资料编辑和上下架必须带当前版本，旧表单返回 409。 |

- 新建商品以 `DRAFT` 入库，成功后 303 返回商品列表，再可从编辑入口进入 A05。编辑只写资料字段，并在相同语句用旧版本限制更新、递增版本。当前上架状态和库存由数据库保留。商品资料变化不回写已成交明细。
- 上架动作要求当前为 `DRAFT`、表单版本有效且商品资料与类目合规。成功后变为 `ON_SALE`，商品出现在公开查询中。库存为 0 时展示售罄。下架仅允许从 `ON_SALE` 转 `DRAFT`，成功后公开详情不再可用。两动作均增版，旧版或状态已变化时返回 409 并提示刷新。
- 补货使用独立表单，只接收正整数 `quantity`，以锁内当前库存为起点计算新值并增版。两端并发更新同一 SKU 时不采用页面旧库存覆盖。每次合法提交代表一次独立补货，确认按钮和提交反馈要清晰。加法溢出时整体拒绝，不改变库存或版本。

### 查单与登记模拟发货

适用 REQ-12 和 BR-01、BR-06、BR-08、BR-12、BR-13。

1. 后台列表可按完整单号、状态和可选 `userId` 查询全站订单，三项按 AND 组合。`userId` 须为正整数且对应既存 CUSTOMER，格式错误 400，未知或 ADMIN 的 ID 为 404。来自 A09 的跳转保留顾客过滤标签并提供清除入口。列表显示创建时间、金额、状态和详情入口。详情取收货与商品快照，显示首个支付凭证、支付和履约时间等已写字段。顾客端使用相同的快照，列表查询仍限制本人。
2. 仅待发货 `PAID` 显示发货入口。管理员核对单号、收货快照和状态后提交，后端先锁当前 ADMIN 操作者并复核身份，再锁订单并复核状态。首次成功转 `SHIPPED`，写入发货时间，303 回详情。支付字段、订单金额、库存和购物车不发生变化。
3. 待支付或已取消订单要求发货时返回 409。订单已经发货或完成时，重复发货显示首次处理结果并保留发货时间。发货是教学状态登记，首版页面只展示项目状态和时间。

### 普通顾客查询、详情与启停

适用 REQ-15 和 BR-01、BR-12、BR-13、BR-16。

1. A08 固定 `role=CUSTOMER`，允许按用户名 `q`、启用状态和页码联合查询，默认状态 ALL、每页 10 条、按 ID 升序。无匹配显示正常空状态，保留条件并给清除入口。只显示教学资料，管理员账号不能被搜索结果带出。
2. A09 读取路径指定的 CUSTOMER，展示账号资料、启用状态及「查看该顾客订单」。未知 ID 或 ADMIN ID 返回 404。订单入口使用 `/orders?userId={id}`，可继续叠加订单号、状态和分页，不改变订单快照或用户端归属规则。
3. 详情上的启用或禁用表单只提交 `targetStatus` 与 CSRF。禁用前提示「后续保护请求需重新登录，已有购物车和订单保留」。事务先锁 ADMIN 操作者并复核身份，再锁目标用户、检查 CUSTOMER 角色，只更新状态及单调推进的身份时间。首次变更或重复同状态均 303 返回 A09，展示数据库实际状态，重复提交不刷新更新时间。
4. 停用普通顾客后，在已有用户端会话打开购物车、结算、本人订单或提交原写表单均要求重登，原结算确认作废。公开商品目录仍可作为游客浏览。启用后通过正常登录恢复本人数据访问，不允许旧结算令牌继续下单。
5. 参数无效返回 400，目标不存在或不是 CUSTOMER 返回 404，管理员身份或 CSRF 无效按 BR-12。技术失败回滚状态。验收要同时观察目标用户、另一个顾客及管理员账号，确认没有越界更新和历史数据丢失。

### 商品相册维护

适用 REQ-16 和 BR-01、BR-03、BR-11、BR-12、BR-15、BR-17。

| 动作 | 输入与校验 | 成功、失败与核对 |
| --- | --- | --- |
| 打开 A10 | 路径 `productId`，读取商品名称、SKU、独立封面、当前 `version` 与相册。 | 按排序值、ID 升序显示缩略图和替代文本。空相册说明前台回退封面，保留新增表单。未知商品 404。 |
| 新增图片 | `imagePath`、可空 `altText`、非负 `sortOrder` 和 `productVersion`。 | 锁商品、校验版本后插入相册行并使商品增版，303 回 A10。字段格式 400、旧版 409，失败不留相册行或增版。 |
| 编辑图片 | 路径 `imageId`，字段同新增。 | 锁商品并校验版本，再按商品及图片 ID 读取目标。真实变更更新行并增商品版本，无变化成功但不增版。跨商品或未知图片 404，旧版本 409。 |
| 移除图片 | 路径 `imageId`、`productVersion`，明确确认目标图片。 | 同一事务检查商品、版本和归属后只删相册行并增版，303 回 A10。末图移除后回封面。重读新商品版本后再删除同一已删图片为 404，直接重放旧版本请求先返回 409，均不重复增版。 |

任一写入都不改库存、SKU、商品状态、独立封面或成交快照，不触碰素材文件。A10 在每次 303 后重新读取当前版本，所有后续表单使用新值。用旧 A05 商品资料表单与相册写操作交叉提交，验证后提交的旧版本为 409。验收还要比较用户端相册顺序、两端同路径图片加载、末图回退、错归属零写入及旧订单快照不变。

### 控制台与运营入口

适用 REQ-14 和 BR-01、BR-12、BR-18。

管理员登录后进入 A02，先从同一读语句取得五项当前计数，再渲染分类、商品（含相册入口）、顾客和订单导航。上架、下架、顾客启停、模拟支付和发货后刷新，相关卡片应按 BR-18 变化。相册维护从商品列表或编辑页进入，以便先定位商品。控制台不直接修改业务数据，待发货卡引导管理员进入 `status=PAID` 的订单列表再核对详情发货。空库显示 0，查询错误显示重试入口且不伪装为空库。新增三模块使用下表追踪验收，当前文档不把规格当作测试通过记录。

## 样例交易与数据对照

在演示库以 `alice` 清空种子车后，加入 2 本 `CSU-LMK-NOTE-01`（每本 18.00 元）和 1 盒 `CSU-GRAD-BOX-01`（每盒 49.00 元），结算页显示两条、合计 85.00 元。以提交前方格本库存 10、礼盒库存 12 为例，成功后两者库存变为 8 和 11，各商品版本增加 1。

| 阶段 | 订单与明细 | 库存与购物车 |
| --- | --- | --- |
| 确认 | 两条、85.00 元的整车确认存于本端会话。 | 库存仍为 10 和 12，原车两条。 |
| 提交成功 | 一张 `PENDING_PAYMENT` 主单，两条明细小计 36.00 和 49.00 元。 | 库存为 8 和 11，已确认两条从本人车清除。 |
| 模拟失败后成功 | 失败时仍待支付。成功后转 `PAID`，保存首次模拟支付凭证及时间。 | 库存为 8 和 11，购物车保留提交后的状态。 |
| 发货 | 从 `PAID` 转 `SHIPPED`，写入首次发货时间。 | 库存与商品版本不再因支付或发货变化。 |
| 待支付取消的独立分支 | 若在支付成功前取消，原待支付单转 `CANCELLED`，保留两条快照明细。 | 以未发生其他库存操作为前提，库存返至 10 和 12，两商品版本再各增 1，购物车不补回。 |

同 SKU 最后一件的竞争和「购买 2、补货 3、原库存 10」并发使用独立测试数据，分别验证只成功一单和库存最终为 11，详见 TST-35、TST-28。
