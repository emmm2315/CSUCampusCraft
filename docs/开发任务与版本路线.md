# CSUCampusCraft 开发任务与版本路线

先交付两个可独立启动、可读取同库主题的工程，再并行开发用户端商品浏览和管理端商品维护。交易实现按持久购物车、整车下单、支付与取消、发货的依赖顺序推进。每一阶段都用可复现的行为和数据结果判定是否可以进入下一阶段。

## 阶段与验收门槛

| 阶段 | 进入条件 | 完成门槛 |
| --- | --- | --- |
| M0 工程初始化 | 两端目录、默认端口、共享库和种子数据约定已统一。 | 两端各自构建，连接同一个 PostgreSQL，显示数据库主题并加载同一份共享图片。按 `INIT-01–05` 留实际证据。 |
| M1 商品与账号 | M0 核心构建、建库和双端读取验证通过。 | 游客能从毕业专区看上架商品。管理员登录后能新增、上架、下架和补货，普通账号与管理员账号会话独立。 |
| M2 交易与履约 | 两端确认购物车、商品库存和订单表的读写约定。 | 普通用户整车下单，模拟支付后由管理员发货，两个端看到同一张订单。待支付订单可取消并恢复正确库存。 |
| M3 综合验收 | M1、M2 的正常流程可用。 | 完成权限、并发、事务回滚和从空库启动的验收。已处理的缺陷有复测记录。 |
| P1 选做 | P0 通过，小组明确选做范围。 | 优先考虑确认收货。选做功能的角色、非法状态和重复请求均有实测结果。 |

## 可认领任务

| 编号 | 任务 | 依赖 | 提交时应能演示 |
| --- | --- | --- | --- |
| T01 | 双端骨架与种子 SQL | 无 | 两个独立应用的根页读取五个数据库主题，完整脚本在空库可导入。 |
| T02 | 用户端首页、主题、搜索和详情 | T01 | 游客浏览及类型筛选符合约定，毕业入口复用毕业分类，零库存、下架和缺图有清楚的表现。 |
| T03 | 双端登录与访问边界 | T01 | 教学账号按角色登录，退出一端后另一端仍可访问。受保护页面可验证会话和角色。 |
| T04 | 管理端分类、商品及补货 | T01，可与 T02 并行，管理写入以 T03 为门槛 | 合法类目和商品可维护，上下架影响前台，补货按增加量生效，旧编辑表单被识别。 |
| T05 | 持久购物车和结算确认 | T02、T03 | 购物车重登可恢复，合并数量与条目版本正确，失效项阻止整车提交。 |
| T06 | 整车下单、订单查询、支付和取消 | T05 | 一次写入主单和全部明细、库存和车条一致。订单快照固定，支付失败可重试，取消只返库存一次。 |
| T07 | 管理端全站查单与发货 | T03，可先用种子订单开发，完成 T06 后联调 | 可按完整订单号定位用户端新订单，已支付订单发货后两端可见。 |
| T08 | 校园素材、毕业专区与成品礼盒 | T02、T04，订单闭环验收依赖 T06 | 素材来源可追溯，礼盒在对应主题下可购，扣减和返还均以盒为单位。 |
| T09 | 回归、双端并发和提交材料 | T02–T08 | 各阶段证据可追到提交版本。实测两账号抢最后一件，以及两个应用并发购买与补货，结果附数据库对照。 |

初始化完成情况只记在[验收与联调清单](验收与联调清单.md)的「初始化实测记录」。M1 至 M3 及 P1 为后续计划。负责人、复核人和提交版本在小组实际认领后登记。

## 每项任务的交接信息

| 字段 | 组员应填写 |
| --- | --- |
| 任务与负责人员 | 任务编号、负责人、复核人。 |
| 范围与依赖 | 受影响的页面、表或公共约定，先合入哪些任务。 |
| 验收 | 用到的 INIT、AC 或 CAMP 编号，实际操作和证据位置。 |
| 实现位置 | 工程名、页面、Controller、Service、Mapper 或 SQL 路径。 |
| 当前进度 | 待认领、开发中、待复核、待联调或完成，附提交或 PR 链接。 |

任务在合入后以验收结果为准。共享 SQL 和跨端行为的改动由两端负责人复核，操作方法见[组内开发协作指南](组内开发协作指南.md)。
