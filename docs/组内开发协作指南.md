# CSUCampusCraft 组内开发协作指南

组内先统一共享字段、环境和交易规则，再并行开发用户端与管理端。阶段和任务编号见[开发任务与版本路线](开发任务与版本路线.md)。发生范围变化时，先在任务里写清页面和数据影响，再同步对应需求与验收项。

## 分工与认领

| 角色 | 主要责任 | 复核重点 |
| --- | --- | --- |
| A 用户端 | 游客浏览、登录、持久购物车、结算、本人订单及模拟支付。 | 真实查询、参数与归属校验、提交前后库存和订单状态。 |
| B 管理端 | 管理员登录、分类和商品维护、补货、全站查单和发货。 | 两级类目、角色隔离、库存版本及发货状态门槛。 |
| C 共享数据与集成 | 维护共享 SQL、初始化记录、演示夹具和联调证据。 | 两端版本、七表约束、跨端数据一致性和事务测试。 |

三人组可以各承担一个角色。两人组可分别负责 A、B，共同承担 C，并给共享 SQL 和每轮联调各定一位牵头人。T03 涉及两端登录，分别实现后由另一位成员用普通账号、管理员账号和两个会话复核。正式成员和分工按小组实际情况填写。课程指导书对每组人数有不同表述，以分组表或老师确认为准。

认领时登记任务号、负责人、复核人、依赖与验收编号。阻塞其他人时，在任务中说明当前差异、需要对方确定的字段或页面、可继续的部分。共用字段与状态以[系统架构与共享数据契约](系统架构与共享数据契约.md)为准。

## 环境与演示数据

从 [README](../README.md) 获取两端构建、配置和启动命令。用户端 `csucampuscraft-user` 和管理端 `csucampuscraft-admin` 各自维护 Maven 工程。两端联调时将 `CSUCAMPUSCRAFT_DB_URL`、`CSUCAMPUSCRAFT_DB_USER` 和 `CSUCAMPUSCRAFT_DB_PASSWORD` 指向同一个 PostgreSQL 库。本机验证可使用独立实例，复测并发时要让两个应用进程同时连接同一测试库。

| 场景 | 准备方法 |
| --- | --- |
| 只验证空库结构 | 在空目标库导入 [01-schema.sql](../database/01-schema.sql)，检查七表。 |
| 联调与验收 | 在空目标库导入 [02-schema-with-demo.sql](../database/02-schema-with-demo.sql)，包含完整结构和种子。 |
| 恢复测试夹具 | 先确认目标是可重建的测试实例，记录要恢复的 SKU、账号和订单。单独恢复夹具，或在新的隔离空库重新导入完整脚本。 |
| 账号测试 | 普通启用账号 `alice`、`bob`，普通禁用账号 `disabled`，管理员 `admin`。教学密码见 [README](../README.md)，数据库连接口令由成员在本地配置。 |

两份 SQL 是 PostgreSQL 空库的两种独立入口。日常应用启动使用已有数据。两端图片源统一放在仓库根目录 `assets/images/`，由各自 Maven 构建打包。更新素材时登记文件名、来源和使用许可，并检查两个端口能加载同一路径。

## Git 和合并流程

1. 从《实验分组表》指定的仓库同步主分支。按任务创建短分支，例如 `feat/T02-catalog`。共享 SQL、跨端状态或接口参数的改动，在修改前先让涉及的同学确认契约。
2. 以可独立复核的改动为单位提交，例如「商品列表支持主题和类型筛选」。提交前检查差异和受影响的用例。仓库提交教学数据和配置示例，真实密码、本机配置、构建结果和临时测试数据库留在本地。
3. 创建 PR 或合并请求，写明任务编号、改动的工程与数据、构建方法、已验证场景和证据。使用 AI 辅助生成的 SQL、权限与事务逻辑，按同样标准人工阅读并运行对应验证。
4. 由另一位成员复核。修改共享 SQL 时，两份初始化脚本的结构需一致，并写清已有开发库如何迁移。影响两端时，负责人分别验证一次，再合入可复现版本。
5. 合入后按[验收与联调清单](验收与联调清单.md)保留提交号、环境、实际数据和结果。修复回归时沿用原场景编号，记录修复版本和复测证据。

## 合入前检查

- [ ] 本次任务对应的需求、实际改动和验收编号能够互相定位。
- [ ] 相关工程按 README 可构建。修改公共字段、筛选参数或状态时，两端均可运行并读到一致结果。
- [ ] 正常流程和相关非法输入、越权、版本冲突或库存不足路径有实测记录。
- [ ] 交易变更的验收材料包含订单、明细、库存、版本和购物车必要前后值。并发与回滚测试在隔离测试环境运行。
- [ ] 若添加新素材或配置，已记录使用方法、来源或本地配置要求。

## 阶段交付与报告

初始化阶段提交两端独立工程、共享 SQL、启动说明和 INIT 记录。业务阶段用管理员上架成品礼盒、用户整车下单并模拟支付、管理员发货这条主线组织联调，并另跑取消、回滚和实际双端并发用例。

最终交付保留源码和静态资源、实际运行环境、需求完成记录、验证证据与可定位的 Git 版本。按课程报告模板填写真实结果和实际成员分工。按指导书安排将实验一报告与实验二报告一起提交。
