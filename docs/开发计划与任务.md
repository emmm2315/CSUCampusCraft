A 为用户端、B 为管理端、C 为共享数据与联调。角色用于分工，认领时填写真实人员。两人组可由 A/B 共同承担 C，分别指定共享 SQL 和每轮联调的牵头人。任务记录包含负责人、复核人、依赖、受影响的页面或表、REQ/BR/TST 编号、进度与证据位置。

## 关键交接点

- 商品与账号交接时，用户端和管理端共同核对类目编码、列表筛选值、可售状态、会话 Cookie、身份取值和错误反馈。商品页需要同时准备正常、售罄、下架和缺图样例。
- 交易开发先接持久车，再接会话内的整车确认，最后接下单写入。联调前确认哪一步从数据库重读价格、哪些请求持有行锁，以及拒绝时保留的购物车和订单状态。
- 模拟支付、取消和发货复用同一订单状态定义。两个应用先用种子订单核对显示和权限，再用实际下单生成的新订单跑交易主线。
- 库存并发和事务回滚分别用独立事务取证。技术层锁行为可先验证，业务验收同时检查订单、明细、库存、版本和失败方购物车。

## 协作和完成定义

1. 按任务开短分支，例如 `feat/task-03-catalog`。对共享字段、状态、SQL 和路由的变更，先更新对应文档并由涉及的两端成员复核。
2. 以可独立复核的范围提交。合并说明记录任务号、涉及工程、复现步骤、用例和证据。教学数据和配置示例进入仓库，本机密码、构建产物和临时测试库留在本地。
3. 功能任务以相关工程可构建、正常与错误路径均通过为完成标准。共享数据变更需核对两份脚本的七表定义，并说明已有开发库如何迁移。
4. 交易变更保留订单、明细、库存、版本和购物车前后值。回归沿用原用例编号，记录修复版本和复测结果。

## 风险与处理

| 风险 | 出现信号 | 处理与复核 |
| --- | --- | --- |
| 双端契约漂移 | 同一分类、状态或路径在两个应用含义不同 | C 同步 SRS、HLD、DDL 和两端用例。共享改动由 A/B 共同复核。 |
| 并发扣库存或重复副作用 | 超卖、重复返库、旧编辑覆盖或失败残留 | 实施 MySQL 锁顺序和条件更新，使用独立事务同步发起请求，核对数据库前后状态。 |
| 演示数据干扰 | 购物车金额不为 85 元或礼盒 SKU 冲突 | 使用隔离库并按用例重置。先清空 alice，再加两件目标商品，已有礼盒用于上下架，新建用空闲 SKU。 |
| 素材缺失或授权待定 | 两端图片地址不同或出现 404 | 使用同一站内资源目录和占位图，记录素材来源与许可。两端同时检查同一路径。 |
| 范围扩张 | P0 未通过就引入自提、真实支付或独立前端 | 依照立项范围分期，变更先写明受影响的需求、表、路由和用例。 |
| 初始化不可复现 | 重启重复导入、配置依赖个人电脑 | 两份脚本在空库二选一，应用正常启动保留数据。MySQL 建表语句分别提交，导入失败后检查错误并用新空库重试，由另一位成员按 README 复现。 |
