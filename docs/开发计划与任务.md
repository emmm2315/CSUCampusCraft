M0 工程初始化与 STEP02 公共页面和安全基础已完成，STEP03 用户端公开目录与 STEP04 双端身份已实现并通过自动实测，组员交叉复核待补；M1 其余业务步骤待开发。初始化与目录的实际覆盖见验收记录，以下未交付步骤仍为待开工计划。文档中的预期结果是完成标准，不是已经执行的结论。

本文件是按依赖排列的执行清单，与 Word 实验指导书共用 STEP01 至 STEP14。默认按顺序验收；分工可以并行，依赖未通过时不能把下游步骤标记完成。实现类名是建议落点，最终入口与数据契约以《系统设计与路由》为准。

## 开始前的阅读和分工

先读[项目立项与范围](项目立项与范围.md)，确认 P0 与 P1；每步再对照[需求与业务规则](需求与业务规则.md)中的 REQ BR。[页面清单与原型](页面清单与原型.md)说明界面与状态，[数据库设计](数据库设计.md)说明字段 CHECK 外键及索引，[系统设计与路由](系统设计与路由.md)规定双端入口，[测试与验收用例](测试与验收用例.md)给出证据标准。运行命令按[README](../README.md)执行。

A 负责用户端，B 负责管理端，C 负责共享数据与联调；认领时换成真实成员。两人组由 A B 分担 C，但每个共享契约和交易事务仍指定一名复核人。先登记负责人 复核人 开始日期与实际完成日期，不预填完成状态。

### STEP04 双端登录与访问控制

状态：待复核（2026-11-14）。本步代码及登录/退出/身份/CSRF 自动实测通过，组员交叉复核与实名待补，M3 前完成。详见[STEP04 实测记录](测试与验收用例.md#step04-实测记录)；下列操作保留为核对清单。

- 阶段与负责人：M1；A B 各实现本端 C 复核。
- 前置：STEP02 的加密 CSRF 与错误处理可用；STEP03 的公开路径已列清。
- 先读：REQ-04；BR-01 BR-12 BR-16。
- 实现落点：两端 AuthController AuthService LoginForm；会话工具和拦截器；store_user Mapper；登录模板。

操作顺序：

1. 实现本端 GET POST /login 与 POST /logout。用户端只接受 enabled CUSTOMER，管理端只接受 enabled ADMIN；用 BCrypt 验证。错误账号 密码 禁用或错端角色使用统一认证失败提示。
2. 登录成功更换本端会话标识，保存账号 ID 和 updated_at 的 UTC 微秒值作为 authStamp。用户端使用 CSUCAMPUSCRAFT_USER_SESSION，管理端使用 CSUCAMPUSCRAFT_ADMIN_SESSION；退出仅清本端会话。
3. 逐次受保护请求重查账号 enabled role 和 authStamp；受保护写操作还须锁用户行后重查，避免与启停竞争。保护购物车 结算 本人订单及后台全部业务页面；公开商品 登录和静态资源按白名单放行。
4. 未登录跳本端登录；通过身份后错角色或越权为 403；CSRF 缺失或错误为 403。返回地址只允许本端合法 GET 路径，成功登录后不自动重放旧 POST。
5. 同一浏览器登录两端、先退用户端再访问管理端，再反向验证。在隔离库禁用已登录账号后请求受保护读写入口，证明会话失去访问能力。

完成核对：两端 Cookie 与身份独立；禁用账号不能登录，已有会话在下次受保护访问时被拦截；未登录与越权可区分，拒绝请求不写数据。

对应验收：TST-05 至 TST-07 TST-31；TST-39 的已有会话规则在 STEP12 补验。

完成证据：Cookie 名和跳转目标、脱敏登录响应、角色与启用状态、退出前后访问、禁用后读写及数据库对照。

失败排查与暂停点：两端相互挤掉登录时检查 Cookie 名；禁用后仍可用时检查拦截器是否只在登录查库。此步是所有业务写入口的前置门槛，身份与 CSRF 未通过时不开放后台维护或交易写入口。

### STEP05 后台分类商品与补货

- 阶段与负责人：M1；B 开发 A 复核公开影响 C 复核数据。
- 前置：STEP03 可观察前台变化；STEP04 已保护管理端写入口。
- 先读：REQ-11；BR-02 BR-03 BR-06 BR-11 BR-12 BR-14。
- 实现落点：管理端 CategoryController ProductController；CategoryService ProductService；分类 商品 Mapper；A03 至 A05 模板。

操作顺序：

1. 先做分类列表与新增。一级 code 去首尾空白后为 1 至 21 字符，22 字符返回 400 且不截断；二级 code 由父 code 加 _STATIONERY 或 _SOUVENIR 生成，完整不超过 32。只允许两级、每父每类型一个。两端 Category.id 保持 IdType.AUTO，检查 Mapper 插入后回填。
2. 实现分类名称 排序编辑与空分类删除；有子类或被任意商品引用均拒绝删除，包含 DRAFT 商品。编辑不改变既有 code 父级或类型，唯一性冲突返回 409。
3. 实现后台商品筛选与草稿新增。只能挂二级类目，校验唯一 SKU、名称 价格和字段长度，金额最多两位小数。新建 DRAFT；留空库存和排序按 0，封面留空用默认资源。
4. 编辑资料提交 product.version，SKU 与库存不作为可写资料字段；锁内检查旧版本。上架 下架检查状态和版本，合法实际变化才递增；用已种子的礼盒做上下架演示，新建另用未占用测试 SKU。
5. 独立补货入口提交正整数增量，在商品现有库存上加值并递增版本，防止溢出；不能用旧表单库存覆盖当前值。前台刷新核对后台资料 上下架及补货都可见。

完成核对：新增分类由 MySQL 生成 ID 且按回填 ID 可查；非法层级 引用删除 重复编码及旧版本不写入。用户端只看上架商品；补货为增量，已有订单快照保留。

对应验收：TST-25 至 TST-28；并发分支 STEP13 运行。

完成证据：新类目 ID、边界码与非法码响应、分类引用、商品前后版本与库存、双端页面、补货请求及结果。

失败排查与暂停点：一级 22 字符不能留到二级才报错；若新增 ID 异常大，检查 AUTO 映射。旧表单覆盖库存或草稿出现在前台时暂停，先统一版本更新和公开查询；并发补货最终在 STEP13 取证。

### STEP14 选做确认收货

- 阶段与负责人：P1；A 开发 B 复核显示。
- 前置：STEP13 P0 通过后，小组明确选择此项；未选择时保持未选做，不影响 P0。
- 先读：REQ-13；BR-01 BR-08 BR-12。
- 实现落点：用户端本人订单详情与 POST /orders/{orderNo}/receipt；OrderService；两端订单显示。

操作顺序：

1. 仅在本人 SHIPPED 详情提供确认收货操作，提交 CSRF；先锁当前 CUSTOMER 复核启用状态 角色和 authStamp，再锁本人订单核对归属和状态。
2. 首次 SHIPPED 转 COMPLETED，写 completed_at；重复本人已完成订单保留首次时间，支付字段与库存不变。
3. 对他人订单 未登录 缺令牌 待支付 已支付 已取消分别尝试操作，按身份 CSRF 资源及状态契约拒绝。
4. 管理端查询同一订单应显示 COMPLETED 和同一完成时间；没有管理员代收货入口，也不新增真实物流或售后。
5. 单独登记选做决定 实现提交 用例及证据；若未选做，隐藏操作并在验收记录写明 TST-36 未选做。

完成核对：只有本人合法已发货订单可首次完成；重复请求不更改首次时间。范围保持在确认动作，不产生付款或库存副作用。

对应验收：TST-36。

完成证据：小组选做记录、完整 SHA、首次与重复响应、完成时间、越权非法状态响应、双端状态和库存对照。

失败排查与暂停点：按钮隐藏不能代替后端授权；若后端允许任意状态完成先修服务校验。P1 用例不通过时只标记 P1 未完成，不能修改 P0 原始结果。
