# CSUCampusCraft 项目需求与双端设计

CSUCampusCraft 是围绕中南大学真实地标与院系设计的现货文创商城。用户按校园主题浏览并购买，管理员维护分类、商品和库存，并处理已支付订单。首页提供「毕业专区」入口，毕业纪念礼盒作为一件有独立售价和库存的成品销售。

工程初始化阶段交付两个独立应用和共享种子 SQL。两端各自访问根页，使用 Thymeleaf 展示从 PostgreSQL 读取的一级主题。下文的账号、交易和商品管理属于首个业务版本，按[开发任务与版本路线](开发任务与版本路线.md)实施，进度以[验收与联调清单](验收与联调清单.md)中的实测记录为准。

## 角色与首版范围

| 角色 | 可执行的操作 |
| --- | --- |
| 游客 | 浏览首页、主题和毕业专区，搜索、筛选、排序、翻页，查看可展示商品。 |
| 普通用户 CUSTOMER | 使用启用的教学账号登录，维护自己的购物车，整车下单，查看本人订单，执行模拟支付或取消待支付订单。 |
| 管理员 ADMIN | 使用启用的管理账号登录，维护分类、商品和库存，查看全站订单并对已支付订单发货。 |

首个业务版本使用收货地址和教学模拟支付。管理员发货后，双方查询同一个订单状态。选做项优先考虑本人确认收货，由小组在基础交易通过验收后决定。个人资料、本人改密、后台普通账号启停和相册维护同属选做。校园自提、个性化定制和真实支付需要另行评估。

## 商品和分类

一级按商品的主要图案主题或发行场景划分，二级按用途划分。书写、学习和办公用品归「文具」，纪念、展示和赠礼商品归「纪念周边」。每件商品只归一个二级分类。带校史馆图案的毕业礼盒按发行场景归「毕业纪念 → 纪念周边」。

| --- | --- | --- | --- |

| 学院风采 | `COLLEGE` | 计算机学院代码便签、材料科学与工程学院晶格笔记本 | 计算机学院像素徽章、建筑与艺术学院建筑线稿立牌 |

商品名与图案是课程项目企划。潇湘校区图书馆、玉带河畔校史馆、潇湘校区体育场及表中的院系名称以学校公开资料为准。商品资源采用组员原创图案或具有相应使用许可的素材，记录来源与许可。网页标注「课程实验 · 模拟商城」，演示账号和收货信息使用测试数据。[中南大学图书馆](https://lib.csu.edu.cn/tsg2026/gk/bgjs.htm)、[校史馆简介](https://dag.csu.edu.cn/jgjj/xsgjj.htm)、[潇湘校区体育场](https://szyjy.csu.edu.cn/info/1025/2999.htm)、[中南大学本科专业目录](https://bksy.csu.edu.cn/jxyz1/xyxl.htm)

- 上表 20 个 SKU 是首批主推商品企划。初始化使用 60 个校园文创商品，每个二级类目 6 个，用于分页、搜索空结果、库存与状态验证。首轮采用站内 SVG 占位资源，实际素材上线与商品功能开发一起推进。
- 一级编码和二级编码全局唯一。二级编码使用一级编码加 `_STATIONERY` 或 `_SOUVENIR`，例如 `LANDMARK_STATIONERY`。后台创建二级时选择类型，同一主题下每种类型各允许一个。分类创建后固定编码与父分类，可编辑显示名称和排序。
- 「全部 / 文具 / 纪念周边」可与一级主题叠加。未选主题时跨全站查所选类型，选定主题时只查其下匹配类型。从二级入口进入时回显对应主题与类型，切换类型用新类型取代原二级条件。列表参数 `ALL`、`STATIONERY`、`SOUVENIR` 分别对应三项。类型由二级编码识别，商品通过 `category_id` 归属二级分类。
- 首次初始化后有五个一级、十个二级。前台从数据库读取分类。后台新增合规主题和二级类目后，前台可查询新增分类。验收如要求前台始终固定五个主题，按课程组确认的口径调整。

## 毕业专区与成品礼盒

- **CAMP-01 毕业专区。** 首页放置毕业主题横幅，入口按 `GRADUATION` 分类编码定位现有商品列表，默认展示毕业主题下所有上架文具和纪念周边。用户可在该列表继续筛选、排序、翻页或看详情。专区使用普通商品展示规则，图文通过站内静态资源维护。
- **CAMP-02 毕业纪念礼盒。** `CSU-GRAD-BOX-01` 归入 `GRADUATION_SOUVENIR`，组合为地标明信片、毕业徽章、毕业帽钥匙扣。种子价为 49.00 元每盒。使用已导入礼盒演示下架和上架，新增验证另用未占用的测试 SKU。用户按盒选数量，订单明细按整盒成交价和数量保存快照。销售、取消与补货只处理礼盒自身的库存，组合中单品各自计库存。

## 用户端页面和交互

| 页面 | 首个业务版本的行为 | 课程追溯 |
| --- | --- | --- |
| 首页 Main | 展示主题导航、毕业入口及商品名称搜索。上架商品按创建时间和 ID 倒序取最多 3 件「新品上架」，按排序值和 ID 升序取最多 4 件「精选推荐」。两栏可出现同一商品。 | FR-G-01 |
| 列表 Category | 用主题、类型、名称关键字、排序和分页查询上架商品。名称包含匹配，关键字去首尾空白、最长 120 字符，按字面处理通配符。默认、价格升降序、新品四种排序。GET 查询，改变筛选或排序回第一页，翻页保留条件。默认每页 6 条，允许 1–50 条。 | FR-G-02 |
| 详情 Product | 按商品 ID 定位，展示分类路径、名称、SKU、封面、相册、售价、库存和设计说明。相册按排序值和 ID 升序，无相册时用封面，缺失资源用统一占位图。零库存显示售罄，下架或不存在显示不可用。 | FR-G-03 |
| 登录 SignonForm | 使用教学账号登录。仅启用的 CUSTOMER 可进入受保护页面。登录前遇到加购等写操作时，登录后由用户再次确认。 | FR-U-01、FR-U-02 |
| 购物车 Cart | 支持加购、合并、修改、移除，展示当前价格、数量与合计。下架、售罄或可售量不足的条目提示原因。统一使用「整车结算」。 | FR-C-01、FR-C-02 |
| 结算 Checkout | 展示当前整车与服务端计算的金额。必填收货人、联系电话和完整地址，去首尾空白后分别限制在 1–50、1–30、1–255 字符。提交后进入待支付订单详情。 | FR-O-01、FR-O-02 |
| 订单 ListOrders、ViewOrder | 展示本人订单，按完整订单号精确查询，可叠加五种状态和分页。详情展示收货、商品、价格快照与业务时间，仅开放当前状态允许的操作。 | FR-O-03、FR-O-04 |
| 支付 Payment | 标明教学模拟支付，显示固定订单金额，分别提供模拟成功和模拟失败操作。 | FR-P-01 |

购物车顶部数量取本人所有条目数量总和，含失效条目，游客为 0。普通用户和管理员都使用本端教学账号登录，后端校验密码散列，登录成功后更新会话标识。

两端分页统一处理页码和每页条数。页码默认为 1，小于 1 的整数按 1 处理。商品浏览默认每页 6 条，其他列表默认 10 条，每页条数允许 1–50。超过末页时保留条件并提供返回有效页的入口。查询完整订单号时去首尾空白，最多 40 字符，空值表示不限单号。

无效参数返回 400，不可用商品或分类返回 404。受保护操作从会话取身份并重查账号状态和归属。未登录或会话过期时进入本端登录页，越权或表单防护失败返回 403。所有写操作由服务端校验角色、输入、业务状态和 CSRF，成功后重定向到可读页面。技术错误显示通用错误页，商品描述和收货信息按普通文本输出。

## 交易规则和共享数据

1. **购物车。** 登录用户与商品组合唯一，重复加购累加。每个 SKU 的总数量为 1–99 的整数，每车最多 20 种 SKU。加购和修改后数量须符合当前库存，修改和移除校验条目版本。购物车按账号保存在数据库，加购和打开结算页均不预占库存。
2. **结算。** 临时确认保存当前用户、全车条目 ID、商品、数量、条目版本和单价。提交时核对数据库整车、状态、价格和库存。车或价变更须重新确认，任一条目失效则拒绝整车提交。金额用 `BigDecimal` 和两位小数，订单总额等于所有明细小计之和。
3. **下单。** 同一事务生成 `PENDING_PAYMENT` 主单和全部明细，记录商品与收货快照，扣可售库存并维护商品版本，精确清理本次确认的条目。任何一步失败则全部回滚。并发提交同一购物车只能成交一次。
4. **支付与取消。** 模拟成功转为 `PAID` 并保存 `MOCK`、唯一凭证和首次支付时间，重复请求读取原成功记录。模拟失败仍待支付。待支付订单由本人取消，同一事务转为 `CANCELLED` 并按明细恢复库存。返还库存只执行一次，商品即使已下架仍返还，用户如需再买须重新加购。支付和取消竞争时只允许一个成功。
5. **发货与完成。** `PAID` 经管理员发货转 `SHIPPED`。选做确认收货时，只有订单所有者可把自己的 `SHIPPED` 订单转为 `COMPLETED`，保存首次完成时间。基础版可以查询和展示种子中的 `COMPLETED`。
6. **两端并发。** 同账号购物车写操作和下单先锁用户。下单用 `SELECT … FOR UPDATE` 按商品 ID 升序锁定所有商品，在锁内重查价格、上架状态和可售库存，确认后再写订单、扣减和清车。取消按同一商品顺序恢复库存，支付与取消先锁订单。不同账号争抢仅剩一件的商品时，只有一单能成交，失败方收到库存不足提示，保留购物车且没有新增主单或明细。价格、状态、库存等商品写操作维护版本，避免旧表单覆盖并发结果。

两端统一使用「待支付 `PENDING_PAYMENT`」「待发货 `PAID`」「已发货 `SHIPPED`」「已完成 `COMPLETED`」「已取消 `CANCELLED`」五种状态。待支付状态的库存由用户取消时释放，界面以真实订单状态为准。

账号、分类、商品、相册、购物车、订单和订单明细分别沿用 `store_user`、`category`、`product`、`product_image`、`cart_item`、`sales_order`、`sales_order_item`。商品快照保存 SKU、名称、封面路径、成交单价、数量和小计，收货快照留在订单主表。两端共享数据结构，通过各自 Service 执行业务。

## 课程追溯与待核对范围

- **工程标识。** 项目名为 CSUCampusCraft。用户端和管理端目录及构建产物分别使用 `csucampuscraft-user` 和 `csucampuscraft-admin`，共用 PostgreSQL 数据库 `csucampuscraft`，会话名和环境变量见[系统架构与共享数据契约](系统架构与共享数据契约.md)。
- **课程范围差异。** 实验指导书列出注册、验证码、后台用户修改和密码重置、商品删除、订单修改和删除。暂按 PRD V1.1 落实教学账号、分类维护、商品上下架和订单合法状态迁移。课程组对差异项、技术标识或固定筛选参数给出新口径后，同步更新两端设计和验收清单。
- **PRD 内部差异。** 排序按第 6.3 节和第 14 章提供明确的四种选项。独立下单请求标识暂按第 3.2、3.3 节划入后续范围，同一购物车只成交一次仍按 P0 验收。
- **数据规模。** 共享 SQL 准备 4 个教学账号、15 个分类、60 个商品、100 条相册记录、10 个购物车条目、10 张订单和 20 条明细。种子用于准备展示和边界数据，真实下单、支付、取消和缺图回退通过运行中的应用验收。

课程追溯依据为《软件开发架构平台》实验指导书实验一、MyPetStore PRD V1.1 第 3–11、14–15 章和配套 SQL。组内实施与交接使用[组内开发协作指南](组内开发协作指南.md)。
