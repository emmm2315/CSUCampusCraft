# CSUCampusCraft 测试与验收用例

本文件定义项目验收用例、测试环境、发布门槛和取证方式。需求与规则见[需求与业务规则](需求与业务规则.md)，页面入口见[页面清单与原型](页面清单与原型.md)与[系统设计与路由](系统设计与路由.md)，字段和数据库核对方法见[数据库设计](数据库设计.md)。

当前处于文档和初始化阶段。MySQL 基线的构建、导入、双端联通、重启与共享图片结果记录在 INIT-01 至 INIT-05。TST-01 至 TST-36 随业务开发执行，页面行为、业务事务、支付和发货按对应 TST 的实际结果判定。

## 环境与夹具

- 用待验收提交分别构建用户端和管理端，指向同一套可重建的 MySQL 8.4/InnoDB 隔离数据库。记录 Git SHA、JDK、Maven、MySQL、浏览器版本和启动命令。当前初始化访问端口为 8080 和 8081。两端分别使用 `CSUCAMPUSCRAFT_USER_SESSION` 和 `CSUCAMPUSCRAFT_ADMIN_SESSION`。
- 按 [README](../README.md) 分别在空库导入结构脚本与演示脚本。演示库包含 4 个账号、15 个分类、60 个商品、100 条相册记录、10 条购物车记录、10 张订单和 20 条订单明细。五个一级主题各有两个二级分类，每个二级分类有 6 个商品。
- 使用 `alice`、`bob` 两个普通账号验证本人数据和跨账号隔离。准备管理员、禁用账号和两个独立会话。每个变更场景使用可恢复夹具，区分种子历史订单和本次应用新建订单。
- 备齐可筛选可翻页的上架商品、有货和售罄商品、下架商品、无相册和缺图商品，以及库存仅 1 件的独立测试 SKU。购物车品种上限测试确保至少有 21 个可加购 SKU。并发和故障注入用例使用独立请求、真实 Service 事务入口和独立数据库连接。
- 在桌面 Chrome 或 Edge 的 1366×768 和 1920×1080 视口检查主流程、空状态、错误提示和提交中的交互。测试使用虚构收货地址，证据中隐藏密码、Cookie 值、确认令牌及个人信息。

### MySQL 底层回归记录

- 在隔离库检查 `alice` 的种子车，6 条中有 3 条因库存不足、下架或售罄而失效。在 SQL 测试事务中清空并按演示数量加入两种商品后，得到 2 条有效记录和 85.00 元合计，变更已回滚。
- 从两端实际 Spring 上下文调用 `CategoryMapper.insert`，分类 `id` 由 MySQL `AUTO_INCREMENT` 发号。管理端和用户端分别回填 504、505，与同连接的 `LAST_INSERT_ID()` 一致，并按回填值查到新增记录。测试分类已回滚，两端 JDBC 会话时区均为 `+00:00`。
- 两个独立 `READ COMMITTED` 事务对同一库存为 1 的商品执行锁定读。观测到第二个事务等待，第一个事务扣库存并提交后，第二个事务读到库存 0。这是 InnoDB 机制验证。两账号真实下单后仍需按 TST-35 核对订单、明细、版本和购物车。

## 重点业务分支与观察点

下表为现有 TST 的细分步骤。每条分支在独立夹具上执行，重试或并发分支例外。除专门测试未登录、越权和 CSRF 的分支外，使用有效本端会话和 CSRF 令牌，确保请求命中预期校验。

| 用例 | 补充操作 | 核对与证据 |
| --- | --- | --- |
| TST-03、TST-30 | 用独立商品分别命中名称中的 `%`、`_` 和 SQL 选择的转义符，再尝试非法类型、排序、状态和条数。查询完整订单号的大小写变体及短前缀。 | 字面搜索不会扩大到通配符结果，非法条件返回 400。完整号按不区分大小写等值匹配，短前缀不会命中。分页计数和条件一致。 |
| TST-05–TST-07、TST-31 | 校验表单缺字段、密码错误、账号禁用、错端角色和会话退出，另模拟非本端返回地址。直接 POST 省略或篡改 CSRF 令牌。 | 缺字段显示 400 和字段提示，凭据错误统一文案且不建立可用登录。退出仅清本端会话，外部返回地址被拒绝。令牌错误返回 403，留存脱敏响应及写入前后对照。 |
| TST-08、TST-10、TST-11 | 对同 SKU 从 1 加到 2，再输入 0、负数、小数或 100。用有效版本提交相同数量后，再用旧版本提交改量或移除。将数量变成超库存及将商品下架分别复测。 | 合并成功只有一行，数量真实变化才增版。有效版本且值相同保持原版本。非法输入或冲突不改数量、版本或库存。失效条目可移除，整车结算被拒。 |
| TST-12、TST-13 | 收货人、电话、地址分别覆盖去空白后为空、边界长度与超长。准备两次同会话确认、一个超期确认，以及另一会话改量或后台改价。 | 字段错误返回 400，原有效确认可继续修正。重开页面后旧令牌、超过服务端有效期的令牌，以及购物车或价格变化的确认返回 409。核对前后订单、明细、库存、商品版本和车条目。 |
| TST-14–TST-16 | 从 10 本方格本和 12 盒礼盒的可售库存起步，按 85 元样例成功提交。另用同等初值执行任一条目在确认后下架或库存不足，以及主单、扣库存、清车各阶段故障。 | 成功时仅一张 85.00 元待支付主单和两条小计为 36.00、49.00 的明细，库存为 8、11，版本各增一次，已确认条目清理。失败时按独立连接读取已提交结果，确认所有本次副作用均回滚。 |
| TST-17、TST-35 | 同账号两份提交使用同一有效确认令牌，另用不同账号和各自确认同时争抢一件。记录同步起点和应用返回后才查询结果。 | 同确认最多成功一次，后续加购不被旧请求清理。不同账号争抢时仅一个账号有新增订单和明细，库存为 0，失败账号车保留。区分应用层测试与单纯数据库锁探针。 |
| TST-20–TST-24 | 记录待支付单的三项支付字段和商品版本。模拟失败、成功、重放成功，再尝试已付款单的模拟失败或取消。对另一单覆盖下架后返库、重复取消、返库中途故障和支付取消竞争。 | 模拟失败三项支付字段仍为空。首次成功留下原凭证与时间，重放保留原值。已付款后失败或取消返回 409。待支付首次取消只返一次，不回填车，下架状态保留。失败分支无部分返库。 |
| TST-25–TST-27 | 创建合法分类与商品后测试重复大小写编码、同父同名、同主题重复类型及非法父类。尝试删除带子类或被草稿引用的类目。新建商品用未占用 SKU，检查草稿、上下架及版本冲突。 | 只有合法变更提交。自动发号的分类按回填 ID 可查。重复或被引用删除返回 409，保留关联。商品草稿不公开，上架或下架只影响对应公开目录和详情。 |
| TST-27、TST-28 | 编辑表单尝试篡改 SKU、库存，再用旧版本提交资料。补货校验 0、负数、小数和溢出。另按库存 10、购买 2、补货 3 执行双端并发。 | 编辑入口保留原 SKU、库存，旧版拒绝。非法补货无库存或版本变化。并发成功分支库存为 11、商品版本共增加两次，两个结果与各自请求对应。 |
| TST-29、TST-36 | 对待支付、已取消、已支付、已发货和已完成订单尝试发货。P1 启用时另覆盖本人收货、重复收货及其他人收货。 | 首次发货仅能从待发货进入已发货，已发货或已完成重复发货保留原时间。待支付、已取消返回 409。收货只改变本人已发货订单的状态与首次完成时间，库存和支付字段保持原值。 |

## 双端演示顺序

1. 管理员将种子礼盒 `CSU-GRAD-BOX-01` 下架再上架，游客从毕业专区检查商品随状态变化。新增商品另跑 TST-25，预先确认测试 SKU `CSU-GRAD-BOX-QA-01` 未占用。
2. 在隔离测试库用 `alice` 登录，用页面移除操作清空全部种子条目，确认空车。只加入 2 本 `CSU-LMK-NOTE-01`，每本 18.00 元，以及 1 盒 `CSU-GRAD-BOX-01`，每盒 49.00 元。确认只有两条，数量为 2 和 1，合计 85.00 元，再提交。记录主单、明细、库存和购物车。
3. 对演示新订单先模拟支付失败，再成功。管理员按完整订单号查单并发货。两端核对同一订单的快照、金额与发货状态。
4. 另建待支付订单验证取消返库存。独立执行旧确认、故障回滚、支付与取消竞争、同车并发提交、双账号争抢最后一件以及双端购买与补货。
